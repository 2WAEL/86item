# 86item — داشبورد الايتمات الموقوفة (Standalone Firebase App)

التطبيق بقى **Standalone بالكامل**: مفيش Google Apps Script ومفيش Google Sheets.
كل الداتا في **Cloud Firestore** والدخول عن طريق **Firebase Authentication**.

```
┌────────────────────────────────────┐         ┌──────────────────┐
│  Firebase Hosting                  │         │  Firebase        │
│  public/index.html                 │────────▶│  Auth (Email)    │
│  public/firebase-backend.js        │◀────────│  Firestore       │
│  (الواجهة كما هي + طبقة البيانات)  │         └──────────────────┘
└────────────────────────────────────┘
```

**الواجهة (UI) ما اتغيرتش**: نفس الـ HTML ونفس الـ CSS ونفس التبويبات والمودالات
والتنبيهات الصوتية والرسوم البيانية (Chart.js). اللي اتغيّر هو طبقة البيانات بس.

- **الواجهة (`index.html`)**: رسم الشاشات + Event Listeners + استدعاء الخدمات. مفيش فيها أي كتابة مباشرة على Firestore.
- **الخدمات (`public/services/`)**: كل اتصال Firebase + منطق الصلاحيات + معالجة Excel. **مفيش أي لمس للواجهة فيها** (مفيش `document.getElementById` ولا `innerHTML` ولا تغيير HTML/CSS).
- **قواعد Firestore**: خط الدفاع الحقيقي — كل عملية بتتحقق من المصادقة + الدور + الفرع.

## 3) الدخول — **قائمة معتمدين، مفيش تسجيل ذاتي**

> ⚠️ **مفيش أي تسجيل تلقائي.** التطبيق مش فيه `createUserWithEmailAndPassword` خالص.
> الحساب لازم يكون **مسجّل ومفعّل مسبقًا** في مجموعة `users` (يعني معتمد من الأدمن).

1. افتح الموقع وسجّل دخول بالإيميل + كلمة السر.
2. **فورًا بعد المصادقة** بيتحقق من الإيميل:
   - **مش موجود في `users`** → يُرفض الدخول + `signOut()` + «عذراً، هذا البريد غير مسجل أو بانتظار موافقة الإدارة».
   - **موجود بس موقوف** → يُرفض + `signOut()` + «حسابك موقوف. كلّم مدير النظام».
   - **موجود ومفعّل** → يدخل لوحة التحكم حسب دوره (`management` / `branch` / `agent`) وفروعه.

### إزاي تضيف مستخدم جديد؟
1. **الأدمن** → ⚙️ **إدارة المستخدمين** → اكتب الإيميل + الدور + المطعم + الفروع → **حفظ**.
   (التطبيق بيحاول يبعتله إيميل "اضبط كلمة السر" لو كان حساب Firebase Auth موجود بالفعل.)
2. **المستخدم** بينشئ حسابه في Firebase Authentication بنفس الإيميل:
   من **Firebase Console → Authentication → Add user** (أو من صفحة تسجيل دخول Firebase لو مفعّلة).
3. المستخدم يسجّل دخول بالإيميل → يدخل فورًا بالصلاحيات اللي الأدمن حددها.

### أول مدير نظام
لو النظام لسه فاضي (مفيش أي حساب في `users`): أول حساب يدخل **بعد** ما يكون معتمد في `users`
بيبقى مدير النظام تلقائيًا. عمليًا: أنشئ حساب الـ Auth من الـ Console، وضيف ملفه الشخصي في `users`
بدور `management` + `isAdmin: true` + `active: true`.

> اسم المستخدم في شاشة الدخول: تقدر تكتب **الإيميل كامل** (مثل `ahmed@company.com`)
> أو تكتب **الاسم بس** (مثل `ahmed`) — في الحالة التانية بيتحوّل لـ `ahmed@item-f8564.firebaseapp.com`.

## 3.1) تسجيل حساب جديد واعتماده (Registration & Approval)

### التسجيل (من شاشة الدخول)
1. اضغط **«حساب جديد؟ سجّل حسابك»** في كارت الدخول.
2. اكتب الإيميل + كلمة السر (6 حروف على الأقل) + **تأكيد كلمة السر**.
3. **«إنشاء الحساب»** ← بيحصل إيه:
   - حساب جديد في **Firebase Authentication**.
   - ملف في `users` بـ **`active: false`** + **من غير أي فروع** + **أقل صلاحية ممكنة** (الدور الافتراضي).
   - **خروج تلقائي من الجلسة** (مفيش دخول قبل الاعتماد).
   - رسالة: «تم إنشاء حسابك بنجاح. حسابك بانتظار موافقة الإدارة.»

> الدخول بحساب لسه موقوف (أو غير معتمد) بيترفض فورًا + `signOut()` + رسالة واضحة.

### الاعتماد (من ⚙️ إدارة المستخدمين)
- الحسابات المعلقة (��للي `active = false`) بتطلع **أول الجدول** وعليها شارة **«بانتظار الموافقة»**،
  وفيه تنبيه فوق الجدول: «في N حساب بانتظار الموافقة — اعتمدهم عشان يقدروا يدخلوا».
- زرار الصف بيكون **«اعتماد»** بدل «تعديل» لأي حساب معلّق.
- بعد الضغط: تفتح نفس الشاشة، وتساهم فيها:
  | الحقل | الوظيفة |
  |---|---|
  | **نوع الحساب / الدور** | قايمة **ديناميكية** من Firestore (مش ثابتة في الكود). |
  | **مدير نظام (Admin)** | صلاحية الإدارة الكاملة (للمانجمنت بس — مانجمنت عادي مش بيقدر يديها). |
  | **المطعم (البراند)** | المطعم المربوط بالحساب. |
  | **الفرع** | فرع واحد أو **«＋ كل فروع المطعم (إضافة الكل)»**. |
  | **اليوزر نشط** | تفعيل/إيقاف — الإيقاف بيلغي جلسات المستخدم فورًا. |

### الأدوار — من Firestore (مش من الكود)
تعريف الأدوار في مستند **`config/roles`**:
```js
{
  roles: [
    { key:'management', label:'مانجمنت',        scope:'all',    grantAdmin:true,  notify:true,  actions:[],                     aliases:[] },
    { key:'branch',     label:'ديسباتشر فرع',   scope:'branch', grantAdmin:false, notify:true,  actions:['logStop','resumeStop'],  aliases:['dispatcher','dispatch'] },
    { key:'agent',      label:'ايجينت (قراءة بس)', scope:'branch', grantAdmin:false, notify:false, actions:[],                     aliases:[] }
  ],
  aliases: { dispatcher:'branch', dispatch:'branch' }
}
```
- `scope`: `all` (يشوف كل برانداته) أو `branch` (فروعه بس).
- `grantAdmin`: يقدر ياخد صلاحية «مدير النظام».
- `actions`: العمليات المسموحة للدور (لو فاضية → الافتراضي حسب `scope`).
- `notify`: هل الإشعارات توصله.
- `aliases`: أسماء بديلة (مثل `dispatcher` = نفس دور `branch`).

> **مفيش أي قائمة أدوار/إيميلات/صلاحيات ثابتة في كود الواجهة أو الباك إند.**
> كل التحقق من الدور بيتم من `config/roles` + مستند المستخدم (`role` / `branches` / `active`).
> مستند الإعدادات بيتعمل تلقائيًا (مرة واحدة) لما أول أدمن يفتح شاشة إدارة المستخدمين.

## 4) إدارة المستخدمين (Firebase Auth)

الباسوردات كلها متmanageة من **Firebase Authentication** (مش متخزّنة في Firestore).
اللي في Firestore هو **الملف الشخصي** بس: الدور / المطعم / الفروع / التفعيل.

### الحقول في شاشة إدارة المستخدمين

| الحقل | الوظيفة |
|---|---|
| **اسم المستخدم** | الإيميل (أو الاسم بس → بيتحوّل لـ `name@item-f8564.firebaseapp.com`). |
| **كلمة السر** | للحساب الحالي بس (بتتغيّر من Firebase Auth مباشرة). لليوزر الجديد: هو اللي يحدده أول ما يسجّل دخول. |
| **نوع الحساب / الدور** | `دسباتشر فرع` · `ايجينت` (قراءة بس) · `مانجمنت` (كل حاجة + تقارير). |
| **مدير نظام (Admin)** | صلاحية الإدارة الكاملة (للمانجمنت بس). |
| **المطعم (البراند)** | المطعم اللي الحساب مربوط بيه — **بيفلتر قائمة الفروع** تحته. |
| **الفرع** | فرع واحد، أو **「＋ كل فروع المطعم (إضافة الكل)」** = يبقى مربوط بكل فروع المطعم دفعة واحدة. |
| **اليوزر نشط** | إيقاف الحساب بيلغي جلساته فورًا. |

### الفرع الواحد ضد "إضافة الكل"

- **فرع واحد** → الحساب يشوف الفرع ده بس (زي الديسباتشر العادي).
- **إضافة الكل** → الحساب مربوط **بكل فروع المطعم المختار** (مشBranch واحد).
  بيظهر في الجدول: `4 فروع (DOKKI، ZAMALEK، MERRYLAND، ELSAHEL)`.
  ولما يدخل، بيبقى عنده **مبدّل فروع** في شاشة الدسباتشر (`فرعي: ▾`) وبيقدر يسجّل إيقاف في أي فرع من فروعه.

> ملاحظة: المانجموت بيشوف كل فروع كل المطعم حسب الفلتر، والديسباتشر/الايجينت بيشوفوا
> الفروع المحددة لهم بس (العزل بيتعمل في الـ backend).

### العمليات

| العملية | إزاي |
|---|---|
| **إضافة مستخدم** | ⚙️ إدارة المستخدمين → اكتب الإيميل + الدور + المطعم + الفرع → حفظ. الحساب بينشأ أول ما يسجّل هو دخول بالإيميل ده. |
| **تفعيل / إيقاف** | نفس الشاشة → checkbox "اليوزر نشط". الإيقاف بيلغي جلسات المستخدم فورًا. |
| **تغيير باسورد حسابك** | نفس الشاشة → عدّل حسابك الحالي وحط كلمة سر جديدة. |
| **باسورد مستخدم تاني** | مش متاح من التطبيق — الأدمن يطلب من المستخدم يعمل "نسيت كلمة السر" من Firebase Console، أو يمسح الحساب ويعمله من جديد. |

## 4.2) رفع المنيو من ملف Excel

⚙️ → **📥 رفع منيو من Excel** (مانجمنت بس).

**قبل الرفع بتختار:**
| الخيار | الوصف |
|---|---|
| **المطعم (البراند)** | `brandId` — المنيو هيتربط بالمطعم ده. |
| **نطاق الفروع** | **فرع محدد بس** أو **كل فروع المطعم دفعة واحدة** (الفرع المختار بيتحدد تلقائيًا). |
| **الملف** | `.xlsx` أو `.csv`. |

**الأعمدة المتوقعة:** `الصنف` (إجباري) · `التصنيف` · `السعر` · `متاح` (نعم/لا).
(التصنيف والسعر ومتاح اختياريين — والقيم بالإنجليزي بتتقبل كمان: Item / Category / Price / Available.)

**اللي بيحصل:**
- الملف بيتقرأ ويترجم لصفوف (بدون أي مكتبة خارجية — قارئ XLSX/CSV مكتوب يدويًا).
- كل سطر بيتنظّف ويتحقق (اسم الصنف إجباري، السعر رقم، "لا/غير متاح" = غير متاح).
- الصنف الموجود بنفس الاسم في نفس الفرع **بيتحدّث** (السعر/التصنيف/التوفر)، والجديدة **بتتنضاف**.
- كل صف بيتخزّن مرتبط بـ `brandId` + `branchId` بالظبط.
- النتيجة: «✓تم استيراد N صنف في M فرع (K صف)».

> **معالجة الحقن:** أي اسم صنف بيبدأ بـ `= + - @` بيتحوّل لنص عادي وقت التصدير (حماية من صيغ Excel).

## 5) مجموعات Firestore

| Collection | المحتوى |
|---|---|
| `restaurants` | المطاعم: `{ id, name, active, createdAt, createdBy, seq }` |
| `branches` | الفروع: `{ key, name, restaurant, active, openSec, closeSec, days[7], ver, … }` |
| `menu_items` | المنيو: `{ restaurant, branch(''=كل الفروع), item, itemKey, category, price, available, active, seq }` |
| `reasons` | الأسباب: `{ restaurant, branch(''=كل الفروع), name, nameKey, enabled, seq }` |
| `item_stoppages` | سجلات الإيقاف: `{ date, item, itemKey, stopSec, startSec, reason, note, restaurant, branch, branchName, open, seq }` |
| `branch_times` | أوقات التحضير/التوصيل (سجل تاريخي): `{ branch, restaurant, prepMin, delMin, by, at, seq }` |
| `users` | الملفات الشخصية: `{ username, usernameKey, email, uid, role, branch, branches[], restaurant, isAdmin, active, ver }` |
| `audit_logs` | سجل العمليات: `{ at, by, role, action, target, details, result, ref }` |
| `notifications` | الإشعارات: `{ at, restaurant, branch, roles, targetUser, title, body, kind, severity, readBy[] }` |
| `shift_log` | ترحيل الشيفت: `{ at, branch, day, open, close, stops, closed, actor, note }` |
| `error_log` | الأخطاء: `{ at, action, by, code, message, detail, stack }` |

**ملاحظات:**
- `item_stoppages.startSec = null` → الصنف لسه موقوف؛ ومن غيره (= وقت التشغيل) يبقى اشتغل.
- كل صف في `branch_times` هو نسخة تاريخية؛ الداشبورد بياخد آخر صف.
- أوقات العمل اليومية في `branches.days[7]` (0 = الأحد).
- `users.ver` بيتغير مع كل تعديل → الجلسات القديمة بتبطل فورًا.
- `users.branches` = قائمة الفروع (مش فرع واحد) — بت-support "إضافة الكل".

## 7.1) ملخص الحماية (تفاصيل كاملة في SECURITY.md)

| الطبقة | الحماية |
|---|---|
| **Firebase Auth** | Email + Password بس · الجلسة في `sessionStorage` · إعادة تأكيد الهوية للعمليات الحرجة · الباسوردات مش في Firestore ولا في الكود. |
| **Firestore Rules** | `request.auth != null` على كل وصول · الحساب لازم يكون نشط · عزل حسب الدور (management / branch / agent) · عزل حسب الفرع · سجل العمليات والأخطاء للأدمن بس · منع تصعيد الصلاحيات · deny-by-default. |
| **حارس الجلسة (UI)** | تحقق عند تحميل الصفحة · تحقق كل 60 ثانية · تحقق عند رجوع التبويب · خروج فوري لو الحساب اتوقّف. |
| **منع الحقن** | تنظيف كل المدخلات + تحقق صارم (إيميل/دور/فرع/أرقام) · HTML escaping في كل المواضع · منع صيغ Excel في التصدير. |
| **الأسرار** | مفيش مفاتيح خاصة في الواجهة · فحص آلي + CI · App Check جاهز للتفعيل. |

> ℹ️ **إعداد `apiKey` بتاع Firebase Web مش سر** — هو مطلوب في المتصفح لكل تطبيق Firebase
> والحماية الحقيقية هي **Authentication + Rules**. أي Service Account أو Private Key ممنوع
> في الواجهة، وفيه فحص آلي بيتأكد من كده.

## 9) ملاحظات أمنية

1. **كلمة السر** مش بتتخزّن في Firestore إطلاقًا — Firebase Auth بيتكفّل بيها.
2. **قواعد Firestore** بتمنع أي حد مش مسجّل دخول يقرأ أو يكتب.
3. **sessions**: بتتخزّن في `sessionStorage` (بتنتهي لما ت closes the tab).
4. **العمليات الحساسة** (مسح الداتا / حذف يوزر / حذف فرع / حذف مطعم) بتطلب
   إعادة تأكيد بكلمة السر عبر Firebase Auth.
5. `window.FB` متاح في الكونسول للفحص السريع (مثلاً `FB.state.item_stoppages`).

## 10) مشاكل شائعة

| العَرَض | السبب | الحل |
|---|---|---|
| «تسجيل الدخول بالإيميل مش مفعّل» | Email/Password مقفول | فعّله من الـ Console (قسم 2). |
| «اسم المستخدم أو كلمة السر غلط» | الحساب مش موجود | أول مرة: اكتب إيميل + كلمة سر جديدة → الحساب بينشأ (موقوف لحد تفعيل الأدمن). بعد كده: كلمة السر غلط فعلاً. |
| «تم إنشاء حسابك بنجاح، بس محتاج تفعيل» | حساب جديد | الأدمن يفعّله من ⚙️ إدارة المستخدمين. |
| «انتهت الجلسة» | الجلسة اتقفلت / اتغيرت | سجّل دخول تاني. |
| الصفحة مش بتتحدّث لحظي | الـ Rules مرفوضة | اتأكد إن `firebase deploy --only firestore:rules` اشتغل وإن الـ user مسجّل دخول. |
